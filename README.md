# 智能工厂 3D · 从来料到入库全流程仿真

一个纯前端（无需后端、无需外部模型资源）的化工车间三维仿真 Demo，用浏览器实时演示
**来料收货 → 原料库 → 提升上料 → 北侧三条产线（合成 / 复配 / 灌装）→ 成品冷却 → 下料 → 成品库 → 入库发运**
的物料流与设备状态。

技术栈：**Three.js + TypeScript + Vite**。车间、设备、货架、车辆均为程序化建模（代码生成几何体），
无 glTF / HDR 等外部资源依赖。

---

## 快速开始

```bash
npm install
npm run dev      # 开发模式，默认 http://127.0.0.1:5173（端口占用时自动顺延）
npm run build    # 类型检查 + 生产构建，输出到 dist/
npm run preview  # 本地预览生产构建
```

> 内网部署：把 `dist/` 丢到任意静态服务器（Nginx / IIS / OSS）即可，无需 Node 运行时。

## 车间布局

厂房 **150m × 60m**（X：−75～75，Z：−30～30），南墙为剖切矮墙，便于俯视。

| 区域 | 位置 | 内容 |
| --- | --- | --- |
| 西厅 | 产线以西，整段留空 | 来料门、卸货暂存、原料桶架 |
| 北墙产线 | 三条沿墙并排，全部贴北墙，各约 29m | A 合成、B 复配、C 灌装，设备靠墙、辊道朝南侧通道 |
| 线尾冷却 | 两条原料线南侧地面 | 成品桶 / 托盘静置降温，再进入灌装 |
| 南侧 | 物流通道、办公楼 | 通道在产线以南；办公楼贴南墙 |
| 东侧 | 成品库与发运 | 入库门在办公楼东侧（朝南看时的右侧） |

三条产线贴着北墙从西往东并排，起点在原料库以东，西端来料区不再被产线占用。每条约 29m，线与线之间留出提升机和下料口。

## 功能清单

### 三维场景
- 150m × 60m 车间，地坪分区、物流通道、月台标线由一张平面图贴图一次画出
- 北侧三条短产线：计量罐、反应釜、熟化塔、压滤、换热器、冷却架、暂存罐、灌装、贴标、码垛机器人
- 辊道贴图滚动；釜 / 塔 / 风机按工位忙闲旋转；信号灯柱随工位状态变色
- AGV ×5、叉车、原料桶架、吨桶、成品托盘；南墙来料门与入库门各有卸货车
- 两层办公楼贴南墙，东立面朝向入库门

### 物料仿真
- 12 个流动托盘。载货随工序变化：原料桶 → 在制品 → 成品
- 托盘状态灯：蓝 = 来料，橙 = 在制，绿 = 成品。原料线进入冷却工位后即为成品
- AGV：FIFO 队列，沿物流通道用 `CatmullRomCurve3` 取货、运送、卸货
- 同一条线上保持间距，前面堵住时后面排队
- 工位状态（作业中 / 待料 / 待机）由仿真反推，不单独写死

### 交互与看板
- 左栏：工艺流程树，显示实时状态与在制数量，点击后镜头平滑推近
- 右栏：今日入库、在制品、平均节拍、OEE、一次合格率、设备在线率，以及近 12 小时产出和设备 OEE
- 顶栏：设备在线数、在制品、AGV 占用、时钟
- 底栏：暂停、0.5×～4×、自动巡检、全景复位、辉光、高 / 中 / 低画质
- 点击场景中的设备可定位到对应工位
- 全景机位按视口宽高比计算距离，并避开侧栏，保证整厂入画

## 二次开发指引

### 改车间布局 / 缩短或加长产线
坐标集中在 `src/world/layout.ts`。

- 三条线贴同一面北墙：`wall: -1` 且 `z` 相同，沿 X 并排。下一条的 `x0` 要比上一条的 `x1` 大出约 11m，留给提升机和下料口
- 线长由 `x0`、`x1` 决定。工位 `x` 必须落在这段里，相邻工位中心距要大于两台设备半宽之和
- `COOLING_YARDS` 在 A、B 线的南侧（通道一侧），不要占用北墙，也不要填进两条线中间的缺口
- 地面文字在 `src/core/textures.ts` 的 `createFloorTexture()`，改线位后要同步色带

新增工位：在对应线的 `stops` 里加一项即可，`factory.ts` 会按 `kind` 生成设备，`flow.ts` 会让物料依次停靠。

### 接真实 MES / ERP 数据
`src/flow/flow.ts` 是物料状态来源，`src/data/mock.ts` 是看板假数据来源。接入时：

1. 在 `mock.ts` 同级新建 `api.ts`，封装 `fetch` / WebSocket；
2. 用真实数据替换 `flow.metrics` 的写入点，或用服务端事件驱动 `Actor.phase`；
3. 若要双向联动，可在 `flow.ts` 增加 `onActorChange` 回调。

### 换成真实 3D 模型
`src/world/equipment.ts` 里每种设备是独立构造函数，换成 `GLTFLoader` 加载的 `Group` 即可，调用方不用改。CAD（STEP / DXF）可先经 CAD Exchanger 或 OCC 转成 glTF 再导入。

### 换成 Unity / UE
本项目是可快速交付的网页 Demo。若需要影视级画质、真机位或直接接 PLC，建议改用 Unity / Unreal 加工业协议 SDK（OPC UA / Modbus / MQTT）。这里的数据流和工位划分可以直接当设计参考。

## 性能

- 桌面端目标 60fps：几何体缓存、共享材质、单张地坪贴图、单向阴影
- 高 / 中 / 低三档分别控制像素比、阴影和辉光
- 移动端用「低」画质。还要再省，可以对非当前工位做 LOD 或按需隐藏

## 已知取舍

- 用物流状态机和运动学动画，不做碰撞和动力学，优先保证看得懂、跑得稳
- 地坪和墙体是表现模型，没有绑真实图纸。生产版本应走 CAD 轻量化导入
- 看板数字是模拟值，没有接真实数据库
